# Dig into Decisions

- 対象を設計ツリーとして捉え、各判断に依存する後続判断を枝として管理する。
- 環境、source、既存資料または利用可能なtoolで確認できる事実は自分で調査し、ユーザーには聞かない。
- ユーザーには、選択またはtrade-offを伴う意思決定だけを質問する。
- 調査中の事実に依存する質問は保留し、前提が解決している別の枝を先に進める。
- 重要な意思決定が事実確認に依存し、その事実を確認できるsource、環境、資料またはtoolが利用不能で、先に進められる別の枝もない場合は、その事実を意思決定質問へ偽装したり`未検証の前提`へ移したりせず、確認不能な事実、阻害されている判断、および再開に必要な入力またはaccessを通常の応答で報告して停止する。
- 回答ごとに設計ツリーを更新し、前提が解決している未決定事項から次の質問を一つだけ選ぶ。
- 幅より深さを優先し、新たな洞察が得られなくなるまで一つの枝を掘り下げてから次へ進む。
- 甘い回答、曖昧な回答、未検証の前提または内部矛盾には、根拠と影響を示して問い直す。
- 質問には選択肢、推奨回答および推奨理由を必ず含める。選択肢外の回答も受け付けるが、主要なtrade-offが未解決なら明確化する。
- 質問には `AskQuestion`、`AskUserQuestion` その他の質問toolを使わず、通常の応答として次の形式を厳守する。

```less
### ❓ Q[番号]: [質問文]

[なぜこの質問が重要か]

- **A** — [選択肢]
- **B** — [選択肢]
- ...

**推奨: [A/B/...]** — [理由]
```

- 一度の応答で質問は一つだけ行い、番号は会話を通じて単調増加させる。
- 前提が解決している未決定事項がなく、重要な枝に暗黙の前提が残っていなければ、同じ質問形式で共通理解に達したか確認する。
- ユーザーが共通理解を確認するまで、実装または計画作成へ移らない。続行を求められた場合は設計ツリーを更新して質問を続ける。
- 共通理解が確認されたら、新しいtaskへそのまま貼り付けて実装を依頼できる自己完結したpromptを作る。元の会話を参照しなければ理解できない表現を残さない。
- 最終応答は、前置きや追記を付けず、prompt一つを収めた単一の四連backtick code blockだけにする。
- Promptには次のsectionをこの順序ですべて含め、該当事項がなくても省略せず`なし`と明記する。
- `決定事項`には実装へ影響する決定だけを挙げ、それぞれに決定理由と主要な棄却案を添える。検討過程全体は引き継がない。
- `未検証の前提`には実装前にsource、環境または適用guidanceから確認できる事実だけを置き、未解決の意思決定を移さない。
- `実装時の指示`にはtask固有の指示に加え、authorityと主要contractを守るtemplateの二規則を含める。
